== Vista de Ejecución

=== Escenario de Registro de Usuario

This scenario describes how a new user registers in the application. The Webapp captures the data and communicates with the Users Service to store the information.

* *Notably*: The separation between the frontend (Webapp) and the backend (Users Service) allows the logic to be decoupled.
* *API Usage*: The Users Service exposes a REST API on port 3000.

[plantuml,"Registration_Sequence",png]
----
actor Usuario
participant "Webapp (React)" as Webapp
participant "Users Service (Node)" as Users

Usuario -> Webapp: Introduce credenciales
activate Webapp
Webapp -> Users: POST /login (user/pass)
activate Users
note right of Users: Valida credenciales \nen Base de Datos
Users --> Webapp: 200 OK (JWT/Sesión)
deactivate Users
Webapp --> Usuario: Acceso concedido al Menú Principal
deactivate Webapp
----
=== Escenario de Inicialización de Partida 
El motor de Rust ahora mantiene un **estado persistente** durante la partida. Este escenario es crucial porque es donde el servidor "elige" su personalidad.

* *Consistencia*: Una vez elegida la dificultad, el bot asignado no cambia hasta que se reinicie el tablero.
* *Estado compartido*: Se utiliza un `AppState` con `Arc<Mutex<String>>` para recordar el bot activo.

[plantuml,"Game_Init_Sequence",png]
----
actor Usuario
participant "Webapp (React)" as Webapp
participant "GameY Engine (Rust)" as Gamey

Usuario -> Webapp: Selecciona Tamaño y Dificultad
activate Webapp
Webapp -> Gamey: POST /reset {size, difficulty}
activate Gamey
note right of Gamey: 1. Crea nueva instancia GameY\n2. Filtra bots por dificultad\n3. Fija **active_bot** en memoria
Gamey --> Webapp: 200 OK (Tablero inicializado)
deactivate Gamey
Webapp --> Usuario: Muestra tablero vacío listo para jugar
deactivate Webapp
----

=== Escenario de Turno de Juego y Persistencia
Este escenario ilustra el ciclo de vida de un movimiento. El motor de Rust no solo calcula la respuesta, sino que detecta el final de la partida y persiste el resultado.

* *Inteligencia*: El motor delega la jugada al bot guardado en el `active_bot`.
* *Persistencia*: Al detectar un ganador, el servicio de Rust se comunica directamente con MongoDB.

[plantuml,"Game_Move_Sequence",png]
----
actor Usuario
participant "Webapp (React)" as Webapp
participant "GameY Engine (Rust)" as Gamey
database "MongoDB" as DB

Usuario -> Webapp: Pulsa en una celda
activate Webapp
Webapp -> Gamey: POST /execute-move {index}
activate Gamey
note right of Gamey: 1. Aplica mov. humano\n2. Carga IA asignada\n3. Calcula respuesta
Gamey -> Gamey: El bot ejecuta su estrategia (Edge/Attacker...)
alt Si la partida termina (Winner != null)
    Gamey -> DB: insert_one(PartidaRecord)
    note right of DB: Guarda fecha, oponente,\ndificultad y resultado real
end
Gamey --> Webapp: 200 OK (Tablero YEN + Winner ID)
deactivate Gamey
Webapp -> Webapp: Actualiza UI (Celdas coloreadas)
Webapp --> Usuario: Muestra el estado actual del juego
deactivate Webapp
----
